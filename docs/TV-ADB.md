# 电视安装、ADB 与自启动

## 安装

从 [Release](https://github.com/xudong7587/ugreen-hdmi-tv-remote/releases/tag/v0.4.1) 选择一个 APK：ARMv7（`armeabi-v7a`，32 位 Android）、ARM64（`arm64-v8a`，64 位 Android）或通用版（`universal`，不确定时推荐）。均要求 Android 6.0 及以上；通用指 CPU 架构，不代表所有品牌固件已经适配。当前 v0.4.1 三份附件是同一个原签名纯 Java APK 的不同下载名称，已安装旧版无需更换。详见 [版本选择](../README.md#电视-apk-怎么选) 和 [更新日志](../CHANGELOG.md)。

安装 APK 后打开一次「HDMI 遥控」，选择 NAS 输入通道。无需配置域名；下方授权工具会自动处理应用标识。

## 无障碍授权

优先尝试「更多设置 → 无障碍与开机自启动 → 打开无障碍设置」。若系统提供列表，启用「HDMI 遥控服务」。如果提示没有入口，使用以下一次性 ADB 流程。

本次雷鸟 Android 11 实测：进入电视「设置 → 系统 → 本机信息/系统信息」，停在信息页，依次短按 ↑ ↓ ← →，出现 ADB 调试开关并开启。不同固件入口可能不同；不要因此关闭安装校验或卸载系统组件。

电脑安装 Android Platform Tools 后连接（替换示例 IP）：

```sh
adb connect 192.168.1.101:5555
adb devices
```

在电视上接受本机调试授权，设备应显示 `device`。然后从仓库根目录运行：

```sh
python tools/tv_accessibility.py --serial 192.168.1.101:5555
```

脚本会确认 APK 存在，保留全部其他无障碍服务，只追加本项目组件，并开启无障碍总开关。检查绑定：

```sh
adb -s 192.168.1.101:5555 shell dumpsys accessibility
```

应在 `Bound services` 里看到本服务。脚本不能绕过固件拒绝的权限，也不能替代下一步的电视自启动管理。

## 自启动（这一步决定重启后能否工作）

在 APK「更多设置 → 无障碍与开机自启动 → 打开电视自启动管理」，或电视系统权限管理中操作：

1. 进入「应用自动启动」。
2. 本次固件在统一「自动管理策略」开启时不能编辑单项；需关闭该策略才可分别设置。此项是全局管理模式，请检查其他应用仍符合自己的偏好。
3. 找到「HDMI 遥控」，开启「允许应用自启动」和「允许应用关联启动」。
4. 重启后不要打开 APK，直接切 HDMI 3，测试方向键。

只执行 `cmd appops set ... APP_AUTO_START allow` 在本次固件上会被自动管理策略覆盖，不能替代 UI 的持久设置。

本次已确认：自启动允许后，系统自行绑定无障碍服务，日常转发无需电脑。旧实验版的 `WRITE_SECURE_SETTINGS` 开机恢复权限在此固件重启后未保留，成功自启动不依赖它；本版本仍保留兼容性恢复代码，但**不要求用户授予此额外权限**。

ADB 只用于首次配置和排错；代码通过 LAN 直接转发，不持续使用 ADB。关闭调试后的完整回归尚未单独测试。

## 撤销本应用授权

```sh
python tools/tv_accessibility.py --serial 192.168.1.101:5555 --disable
```

仅移除本项目服务，不恢复过时快照覆盖别的服务，不关闭系统无障碍总开关。也可卸载 APK，并在电视权限管理中关闭它的自启动权限。

## 重启到 HDMI 的边界

实测电视默认重启回首页；本项目不改变系统开机入口。后台自启成功不代表电视会自动回到 HDMI。开机停留 HDMI 且无新切源通知的场景尚未验证。
